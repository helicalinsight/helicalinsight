# MongoDB Database Connectivity for Helical Insight

## Summary

Helical Insight already shipped most of the scaffolding needed for a MongoDB
connection (a built-in "Mongodb" tile in the *Add Datasource* screen, a
`NoSQLLoader` extension point, a `mongo-java-driver` dependency), but the one
piece that actually makes it work — a real `NoSQLLoader` implementation for
Mongo — was missing/broken. This change fills that gap so MongoDB can be
configured, tested and (optionally) queried as a data source, without
touching any other data source type.

## What was actually missing

Digging into the codebase turned up the following:

* The **"Mongodb" tile** in `Add Datasource → No SQL & Big Data` is already
  generated by `hi-repository/System/Admin/Static/DataSourcesList.groovy`
  and posts `dataSourceProvider: "noSql"`, `driver:
  "com.helicalinsight.nosql.mongo"`.
* `NoSqlDataSourceProperties#getSubType()` resolves the NoSQL "subtype" from
  that `driver` value, and `NoSqlUtils#getNoSqlImplementation(subType)` looks
  up a **Spring bean whose name equals that subtype string** — i.e. Helical
  Insight expects a bean literally named `com.helicalinsight.nosql.mongo`
  implementing `com.helicalinsight.datasource.nosql.NoSQLLoader`.
* The only class that ever registered under that bean name was
  `MongoDrillLoader`, which is marked `@Deprecated`. Its `testConnection()`
  never actually verified MongoDB reachability in a reliable way, and its
  `loadToMiddleWare()` would throw if the (optional) Drill middleware wasn't
  reachable — meaning saving/testing a Mongo connection was effectively
  broken out of the box.
* `mongo-java-driver` (v3.12.10) was already declared as a dependency at the
  root POM and inherited by the `core`/`adhoc` modules, so no new
  dependency/version work was required — it just wasn't being used.

## What changed

| File | Change |
|---|---|
| `server/adhoc/.../services/nosql/MongoNoSQLLoader.java` | **New.** Concrete, working `NoSQLLoader` implementation for MongoDB, registered as Spring bean `com.helicalinsight.nosql.mongo` (same name the existing UI tile already sends — no front-end or config changes needed). |
| `server/adhoc/.../services/MongoDrillLoader.java` | **Removed.** Deprecated/broken implementation that used the same bean name; replaced by `MongoNoSQLLoader` so there is no bean-name collision. |
| `server/core/.../managed/jaxb/NoSqlProperties.java` | Doc-comment only: corrected the stale example payload to the real, working field/bean-name contract. |

### `MongoNoSQLLoader`

* **`testConnection(formData)`** — connects with the official MongoDB Java
  driver (`MongoClients` / `MongoClientSettings` / `ConnectionString`) and
  runs a `ping` command. This is a genuine connectivity + auth check and
  does **not** depend on any optional middleware, so the *Test Connection*
  button in the UI now does what it says. It honours:
  * `jdbcUrl` (or `url`) — a MongoDB connection string, e.g.
    `mongodb://host:27017/mydb` or `mongodb+srv://cluster/mydb` (this is
    what the UI already builds from the host/port/database fields on the
    Mongodb tile).
  * `userName` / `password` — optional credentials, layered onto the
    connection string if it doesn't already embed them.
  * `authMechanism` — optional (`SCRAM-SHA-1`, `SCRAM-SHA-256`, `PLAIN`,
    `GSSAPI`, `MONGODB-X509`); defaults to MongoDB's default negotiation.
  * `ssl`, `timeOut`, `maxWait` — optional TLS/timeout tuning, same
    convention used by the other NoSQL loaders in this codebase.
* **`loadToMiddleWare(formData)`** — when the optional Apache Drill
  middleware is enabled (`System > Admin > Drill Configuration`), the
  connection is registered as a Drill `mongo` storage plugin — the exact
  same mechanism Helical Insight already uses to make CSV/JSON sources
  queryable via SQL (`DrillCsvDataSourceCreator`). That makes the MongoDB
  connection immediately usable in ad-hoc/SQL reports through Drill's
  existing JDBC connectivity, with zero changes to the query-execution
  layer. If Drill isn't enabled, this step is skipped with a log warning
  instead of failing — so a MongoDB connection can always be created and
  tested, and gains SQL query support once Drill is turned on.

No existing data source type, connection provider, or front-end code was
modified — this is purely additive at the `NoSQLLoader` extension point the
application already defines for this purpose, so it does not affect any
other database driver's behaviour.

## How to configure/use a MongoDB connection

1. In Helical Insight, go to **Datasources → Add Datasource → No SQL & Big
   Data** and select **Mongodb**.
2. Fill in `Host`, `Port` (default `27017`), `Database`, and optionally
   `Collection`, `Username`/`Password`.
3. Click **Test Connection** — this now performs a real MongoDB `ping`
   using the values you entered and reports success/failure with a
   meaningful error message (auth failure vs. unreachable host vs. bad URL,
   etc.).
4. Click **Save**. The connection is stored like any other data source.
   * If Drill middleware is enabled (`hi-repository/System/Admin/
     drillConfig.xml` → `<enabled>true</enabled>`, configured under
     **System → Admin → Drill Configuration**), the connection is also
     registered as a Drill `mongo` storage plugin, so it can immediately be
     used to build ad-hoc reports via SQL.
   * If Drill middleware is not enabled, the connection still saves
     successfully; enabling Drill later and re-saving the connection will
     register it for SQL querying.

### Advanced / optional fields

These can be supplied through the connection JSON (e.g. for the
`Access`/`Advanced` connection editor) for finer control:

* `authMechanism`: `SCRAM-SHA-1` | `SCRAM-SHA-256` | `PLAIN` | `GSSAPI` |
  `MONGODB-X509`
* `authDatabase`: database to authenticate against, if different from the
  target database
* `ssl`: `true`/`false` to force TLS
* `timeOut`: connect timeout in ms
* `maxWait`: server selection timeout in ms

## Testing performed

The sandbox this change was produced in has no network access and no
pre-populated Maven repository, so a full `mvn install` could not be run
here. Before merging, please run:

```bash
cd server
mvn -pl core,adhoc -am install -DskipTests
```

and validate end-to-end against a real MongoDB instance:

```bash
docker run -d --name mongo-test -p 27017:27017 mongo:6
```

then use the UI flow above (Test Connection, Save, and — if Drill is
enabled — build a simple ad-hoc report against a collection) to confirm
behaviour.
